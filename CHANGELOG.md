# Changelog

Rustine is a hard fork of [Gobley](https://github.com/gobley/gobley) 0.3.7, and its first release is
1.0.0. The entries for 0.3.7 and older versions describe Gobley releases.

## [Unreleased](https://github.com/lidory-dev/rustine/compare/v0.3.7...HEAD)

### Breaking Changes

- Renamed the project from Gobley to Rustine:
  - The plugin IDs `dev.gobley.cargo`, `dev.gobley.uniffi`, and `dev.gobley.rust` are renamed to `dev.lidory.rustine.cargo`, `dev.lidory.rustine.uniffi`, and `dev.lidory.rustine.rust`.
  - The Maven group `dev.gobley.gradle` is renamed to `dev.lidory.rustine.gradle`, and the `gobley-gradle*` artifacts are renamed to `rustine-gradle*`.
  - The Kotlin packages `gobley.gradle.*` are renamed to `rustine.gradle.*`, and classes like `GobleyHost` and `InternalGobleyGradleApi` are renamed to `RustineHost` and `InternalRustineGradleApi`.
  - The crates `gobley-uniffi-bindgen` and `gobley-wasm-transformer` are renamed to `rustine-uniffi-bindgen` and `rustine-wasm-transformer`.
  - The Gradle attributes `dev.gobley.*` are renamed to `dev.lidory.rustine.*`.
  - The Kotlin packages of the Kotlin/JS glue code generated for WASM targets are renamed from `gobley.wasm.*` to `rustine.wasm.*`, and the `__gobley_add_to_stack_pointer` WASM export is renamed to `__rustine_add_to_stack_pointer`.
- Gradle 8.11 or higher is required, as the Gradle plugins are now built with Gradle 9.3.1.
- Android Gradle Plugin (AGP) 9.1 or higher is required. AGP 8 is no longer supported. AGP 9.1 requires Gradle 9.3.1 or higher and JDK 17 or higher, and Kotlin 2.4.0 or higher is recommended.
- Android modules must be either `com.android.application`/`com.android.library` modules using the built-in Kotlin support of AGP, or Kotlin Multiplatform modules using `com.android.kotlin.multiplatform.library`. The `org.jetbrains.kotlin.android` plugin, Kotlin Multiplatform modules applying `com.android.application` or `com.android.library` with `androidTarget()`, and the `android.builtInKotlin=false`/`android.newDsl=false` opt-outs are not supported.
- In `com.android.application` and `com.android.library` modules, dependencies are added to AGP configurations like `implementation` and `test<BuildType>RuntimeOnly` instead of Kotlin source sets.
- In Kotlin Multiplatform libraries, Android local unit tests use the `androidHostTest` source set instead of `androidUnitTest`. Host tests must be enabled using `kotlin { android { withHostTest {} } }`.
- Kotlin Multiplatform libraries using `com.android.kotlin.multiplatform.library` have a single Android variant, so all builds of these libraries and of the apps using them embed the Cargo build selected by `androidVariant`. It defaults to the release Cargo build only when the requested task names contain `release` or start with `publish` (e.g., `assembleRelease`, `bundleRelease`, `publishToMavenLocal`), and to the debug Cargo build otherwise, e.g., for `./gradlew build`. Set `cargo { androidVariant = ... }`, for example using a Gradle property, to choose the Cargo build explicitly.
- Rust functions can't be called from Compose previews in Kotlin Multiplatform libraries using `com.android.kotlin.multiplatform.library`, as these libraries have no debug variant to add the Rust library for the host to.
- Moved the ProGuard rule file generated by the UniFFI plugin from `build/generated/uniffi/androidMain/generated-proguard-rules.txt` to `build/generated/uniffiProguardRules/generated-proguard-rules.txt`.
- Upgraded UniFFI from 0.29.4 to 0.32.2. Rust crates must depend on UniFFI 0.32 (`uniffi = "0.32.2"`). The bindgen can't read the metadata of libraries built with older UniFFI versions, and the bindings fail to initialize when the Rust library uses another UniFFI version, as the UniFFI contract version changed from 29 to 30 and UniFFI 0.31 changed the checksums of methods.
- Rust 1.88 or higher is required, as UniFFI 0.32 and its dependencies require it. `rustine-uniffi-bindgen` and `rustine-wasm-transformer` declare `rust-version = "1.88"` and should be installed with `cargo install --locked`. Packages that don't use `resolver = "3"`, the default of the 2024 edition, may need it to make Cargo pick dependencies supporting their Rust version, e.g., `cargo-platform` 0.3.2 instead of 0.3.3, which needs Rust 1.91.
- Breaking changes inherited from UniFFI 0.30 to 0.32:
  - UDL-defined trait interfaces must be marked with `#[uniffi::trait_interface]`.
  - `[ByRef] bytes` arguments in UDL map to `&[u8]` instead of `&Vec<u8>` in Rust.
  - The bindings generation fails for async primary constructors in the crates whose bindings are generated, which the bindings left out before. Add them to the `exclude` setting, e.g., `exclude = ["MyObject.new"]` in `uniffi.toml`.
  - `&[u8]` and `[ByRef] bytes` arguments are not supported in async functions, methods, and constructors, and in the methods of callback interfaces and traits that Kotlin can implement. The bindings generation fails for them.
  - On `wasm32` targets, which the Cargo plugin builds for Kotlin/JS targets, the futures of async functions and methods must be `Send`, unless the crate enables the `wasm-unstable-single-threaded` feature of `uniffi`.
  - Rust implementations of traits that Kotlin can implement are passed back to Rust as the original object, instead of a wrapper that calls it through Kotlin, so passing one to Rust increases its `Arc` strong count.
- Renamed `NoPointer` to `NoHandle` in the bindings, without a deprecated alias, as objects cross the FFI as `u64` handles since UniFFI 0.30. On JVM, Android, and Kotlin/Native, the classes of objects take `constructor(withHandle: UniffiWithHandle, handle: Long)` instead of `constructor(pointer: Pointer)`, and `uniffiClonePointer()` is renamed to `uniffiCloneHandle()`, which returns a `Long`.

### New Features

- AGP 9.1 support. Rust libraries, UniFFI bindings, and generated ProGuard rules are added to Android variants using the AGP Variant API.
- `HasAndroidVariant.androidVariant` (`cargo { androidVariant = ... }` and `cargo { builds.android { androidVariant = ... } }`) to choose the Cargo build embedded into Kotlin Multiplatform libraries using `com.android.kotlin.multiplatform.library`, which have no build types. It defaults to `Variant.Release` when release builds or publishing tasks are requested in the command line, and to `Variant.Debug` otherwise.
- Publishing the generated ProGuard rules with Kotlin Multiplatform libraries using `com.android.kotlin.multiplatform.library`. The UniFFI plugin turns on `consumerKeepRules.publish` when `generateProguardRules` is `true`.
- `exclude`, `rename`, and `mutable_records` bindgen settings, and the corresponding `exclude`, `rename`, and `mutableRecords` properties of the `generateFromLibrary {}` and `generateFromUdl {}` blocks. They apply to the crate whose config sets them. In library mode, the bindgen's `--config` option sets them for the crate selected with `--crate`, or for the only crate of the library.
- Methods of records, enums, and errors, which become members of their Kotlin classes, also for records without fields. The bindings generation fails for the methods of flat errors.
- `Display`, `Debug`, `Eq`, `Hash`, and `Ord` exported by records, enums, and errors, which override `toString()`, `equals()`, `hashCode()`, and `compareTo()` and implement `Comparable` for `Ord`. Flat enums can only export `Display` and `Debug`, and flat errors implement no traits. The bindings generation fails for a flat enum exporting `Eq`, `Hash`, or `Ord`, and for a flat error exporting `Ord`.
- `Ord` exported by objects, which implement `Comparable`. Objects exporting `Debug` without `Display` use it for `toString()`.
- `uniffiIsDestroyed` property of objects ([mozilla/uniffi-rs#2825](https://github.com/mozilla/uniffi-rs/pull/2825)).
- `&[u8]` and `[ByRef] bytes` arguments are passed to Rust without a `RustBuffer` and still take a `ByteArray` in Kotlin. The array is pinned without copying on Kotlin/Native, and copied to native memory on JVM and Android, which requires JNA 5.12 or higher.
- Custom types over enums and objects thrown as errors ([mozilla/uniffi-rs#2658](https://github.com/mozilla/uniffi-rs/pull/2658)). The bindings generation fails when the builtin type is not used as an error too.
- Objects implementing the traits of other crates ([mozilla/uniffi-rs#2430](https://github.com/mozilla/uniffi-rs/issues/2430)).
- `HashSet` and `Box<T>` types, recursive records and enums, `#[uniffi(default)]` without a literal, defaults of the fields of enum variants, traits exported with `#[uniffi::export(foreign)]` or `#[uniffi::export(rust, foreign)]`, and docstrings of custom types.
- Renaming types, record fields, and enum variants with the proc-macro `name = "..."` attribute ([mozilla/uniffi-rs#2661](https://github.com/mozilla/uniffi-rs/pull/2661), [mozilla/uniffi-rs#2783](https://github.com/mozilla/uniffi-rs/pull/2783) & [mozilla/uniffi-rs#2794](https://github.com/mozilla/uniffi-rs/pull/2794)), `async_runtime` on trait exports ([mozilla/uniffi-rs#2899](https://github.com/mozilla/uniffi-rs/pull/2899)), and literal suffixes in the discriminants of enums ([mozilla/uniffi-rs#2926](https://github.com/mozilla/uniffi-rs/pull/2926)). See the [UniFFI changelog](https://github.com/mozilla/uniffi-rs/blob/v0.32.2/CHANGELOG.md) from v0.30.0 to v0.32.2 for the other changes on the Rust side.
- Checks of the UniFFI contract version and of the API checksums in the Kotlin/Native bindings, like in the JVM and Android bindings. `omit_checksums` turns off the checksum checks.
- The stack trace of unexpected errors thrown by Kotlin implementations of callback interfaces and traits is reported to Rust.

### Fixes

- Made the Cargo plugin embed the Rust libraries into Android variants of custom build types and product flavors. Build types whose names contain `debug` use the debug Cargo build, and the other build types use the release Cargo build, both in the `.apk`/`.aar` files and in local unit tests.
- Made the Rustine plugins work whether they are applied before or after the Android Gradle plugins.
- Made the UniFFI plugin prefer the default `androidx.annotation` version (1.8.2) instead of the `kotlinx-coroutines` version.
- Made project dependencies declared with `api`, `implementation`, or `compileOnly` in single-platform Android or Kotlin/JVM modules propagate the Rust runtime libraries and the UniFFI configurations of the dependencies.
- Fixed ambiguous variant errors when a module using Rustine depends on a project not using Rustine, such as a plain `com.android.library` project, by resolving such dependencies leniently.
- Made `installUniffiBindgen` and `installWasmTransformer` reinstall a crate set with `bindgenFromPath` or `wasmTransformerFromPath` when its sources, or the manifests, lockfiles, toolchain files, or Cargo configurations in its ancestor directories change. Before, the tasks kept using the binary built from the old sources.
- Fixed `u8` and `u16` values returned with the wrong signedness by JNA direct mapping on some platforms, such as Android ARM32, which broke the checksum checks ([mozilla/uniffi-rs#2897](https://github.com/mozilla/uniffi-rs/pull/2897) & [mozilla/uniffi-rs#2935](https://github.com/mozilla/uniffi-rs/pull/2935)).
- Fixed enums whose variants are named like the types of their fields, e.g., `enum Value { Amount(Amount) }`, or like `List`, `Map`, or `Set`, also for the variants of errors ([mozilla/uniffi-rs#2698](https://github.com/mozilla/uniffi-rs/pull/2698)).
- Prevented "Expression is unused" warnings in the generated code ([mozilla/uniffi-rs#2949](https://github.com/mozilla/uniffi-rs/pull/2949)).
- Made the UniFFI plugin keep the `into_custom` and `from_custom` aliases of custom types in `uniffi.toml`. Before, the conversions of such custom types were empty in library mode.
- Made the bindgen accept crate roots without a `uniffi.toml` file in library mode.

### Dependencies

- Built with Gradle 9.3.1, AGP 9.1.0, and Kotlin 2.4.10. The Kotlin API and language version of the Gradle plugins are set to 2.2.
- Upgraded UniFFI from 0.29.4 to 0.32.2. The Rust crates are built with Rust 1.90.0.
